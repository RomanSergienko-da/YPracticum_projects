# Портфолио проектов: аналитика и A/B‑тесты

Здесь собраны проекты, где я работал с продуктовыми метриками, проводил A/B‑тесты, строил воронки, делал сегментацию и оценивал экономику каналов (в рамках Яндекс Практикума).
В фокусе - проверяемые выводы: от подготовки данных до статистической валидации и практических рекомендаций для команды.

---

## Проекты

| Название проекта | Описание | Стек |
| --- | --- | --- |
| [Анализ метрик и юнит-экономики маркетплейса](https://github.com/RomanSergienko-da/YPracticum_projects/tree/main/marketplace-unit-economics) | Рассчитал продуктовые и маркетинговые метрики, проанализировал воронку, удержание и эффективность каналов привлечения. Провёл A/B‑тест механики бонуса на первую покупку: конверсия в покупку выросла с 1.06 % до 7.5 %, ARPU - с 12.6 до 131.2 руб. Эффект подтверждён статистически и обусловлен ростом числа покупателей. | Python (pandas, NumPy, SciPy, statsmodels, scikit‑learn), SQL, PostgreSQL, Matplotlib, Seaborn, A/B‑тесты, расчёт LTV/CAC/ROI, проверка статистической значимости |
| [Сервис доставки еды: оптимизация воронки](https://github.com/RomanSergienko-da/YPracticum_projects/tree/main/food-delivery-analytics)  | Выявил главный провал воронки - подтверждение телефона в мобильном приложении (конверсия 55 % против 90 % на десктопе). Провёл RFM‑сегментацию пользователей и кластеризацию ресторанов (K‑Means) для выделения групп с разной моделью поведения. Результаты использованы для приоритизации доработок приложения и работы с партнёрами. | Python (pandas, scikit‑learn, Matplotlib, Seaborn), SQL, PostgreSQL, RFM‑сегментация, кластеризация K‑Means, анализ воронок |
| [Анализ системы метрик приложения](https://github.com/RomanSergienko-da/YPracticum_projects/tree/main/entertainment-app-unit-economics) | Проанализировал LTV, CAC, ROI, DAU, MAU, Retention и Stickiness в первые 28 дней после запуска нового контента. Сравнил каналы привлечения, оценил сроки окупаемости, выявил каналы с отрицательной, нестабильной и положительной окупаемостью. Показал, что рост вовлечённости сопровождался ухудшением экономики отдельных каналов. | Python (pandas, NumPy, SciPy, statsmodels), SQL, PostgreSQL, расчёт юнит‑метрик, анализ динамики, оценка окупаемости каналов |
| [Финтех-приложение для онлайн-торговли финансовыми активами: A/B‑анализ онбординга](https://github.com/RomanSergienko-da/YPracticum_projects/tree/main/finance-app-onboarding-ab-test) | Оценил влияние обучающего онбординга на поведение начинающих инвесторов в Латинской Америке. Эксперимент показал: углублённое обучение не снижает конверсию в первый депозит и значимо повышает повторные пополнения (+83 % конверсии из первого во второй депозит). Бутстрап‑анализ выявил полярное поведение пользователей («осторожные» снижают суммы вложений, «вовлечённые» - увеличивают). Рекомендована гибкая система онбординга (быстрый старт / глубокое погружение) и детальный разбор этапа завершения онбординга. | Python, pandas, NumPy, SciPy, statsmodels, Matplotlib, Seaborn, A/B‑тесты, бутстрап|
| [Исследование рынка стартапов](https://github.com/RomanSergienko-da/YPracticum_projects/tree/main/startup-market-research) | Проанализировал 40 747 стартапов для оценки инвестиционной модели. Подготовил и очистил датасет (проверка пропусков/дубликатов, валидация ключей), разделил смешанную таблицу на сущности «компании» и «раунды». Ключевые выводы: медиана точнее среднего отражает типичный объём финансирования (медиана 0.6 млн , для компаний с ненулевым финансированием  2.56 млн); число раундов коррелирует со статусом компании (у closed и ipo - больше раундов, у acquired - меньше); выявлено 1 615 сделок с нулевой стоимостью (чаще в software, web, enterprise, biotech). Результаты помогают выделять признаки для оценки стартапов. | Python, pandas, NumPy, Matplotlib, Seaborn |
